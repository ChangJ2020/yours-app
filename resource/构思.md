Yours App (YA) 系统设计与需求规格说明书 (PRD)1. 系统概述与定位系统名称：Yours App（简称 YA）定位：基于自然语言交互的零代码应用即时生成平台（Form/Data-Driven NL2App）。核心理念：用户无需任何编程知识与拖拽配置经验，仅需用自然语言表达业务诉求，通过多轮问答对话即可自动化生成即开即用的轻量级业务管理应用（如工时打卡、库存管理、客户登记、报销申请等）。当前版本范围（MVP 阶段）：免鉴权体系：YA 平台与生成的子应用均不设登录/注册系统，聚焦验证核心业务闭环与生成逻辑。单机/本地运行：生成的应用数据直接保存在本地（如 LocalStorage / IndexedDB / 单机轻量数据库）。模板库留空：预留模板接口，当前仅跑通从零自然语言创建与迭代链路。2. 核心架构：配置驱动引擎（Schema-Driven Architecture）为了让系统具备极高的稳定性与可维护性，系统采用“Spec 规格说明书 + 通用运行时引擎”架构，而非直接生成不可控的源码：[用户自然语言输入] 
       │
       ▼
[AI 交互 Agent (Skill)] ──(多轮对齐功能)──> [生成结构化 App Spec (JSON)]
                                                    │

3. 系统交互流程与状态机系统整体交互分为 5 个明确阶段，并支持随时回退与二次增量迭代：[1. 需求描述] ──> [2. 功能清单对齐] ──> [3. 详细 Spec 确认] ──> [4. 应用生成与运行]

详细步骤规范：阶段 1：需求描述（Requirement Gathering）用户输入初始需求（例如：“我需要一个记录员工工时的 App”）。AI 提取核心业务实体（Entity），推导使用场景与数据流向。阶段 2：功能清单生成与增删调整（Feature Ideation & Refinement）AI 返回概括性的核心功能模块清单（带序号的模块名及简要说明）。用户进行自然语言增删改（例如：“增加记录月度优秀员工的功能”、“去掉工时审核步骤”）。AI 实时输出更新后的功能清单，直至用户发送确认指令（如“功能没问题，继续”）。阶段 3：详细规格说明确认（Spec Confirmation）AI 将功能清单细化为明确的页面/表单视图、字段定义（名称、类型）、操作行为。提供清晰的文本概览供用户最终审阅。分支处理：用户确认：进入阶段 4 启动应用渲染。用户取消/提出修改：平滑回退至阶段 2 继续微调。阶段 4：App 生成与即时运行（App Generation & Runtime）系统解析最终确认的 App Spec，动态挂载路由与组件，实例化数据表结构。用户可直接在界面上进行表单提交、数据查看、检索筛选、数据导出（CSV）等操作。阶段 5：版本迭代（App Iteration）在已生成的子应用右上角常驻“用 AI 迭代此 App”对话入口。用户输入追加需求（例如：“在工时表单增加加班类型字段”）。AI 基于已有的 App Spec 执行增量更新（Patch/Diff），升级版本号，同时保留已有历史数据。4. 5. 核心 Skill 设计：App 生成与迭代 Agent在系统构建时，负责交互的 Agent 遵循以下 Prompt/Skill 逻辑：Skill 角色与行为准则角色：Yours App 专属产品架构师 Agent。输入格式：用户的自然语言诉求 / 增删改反馈。输出规范：交互阶段（阶段 1~3）：使用简洁、结构化的 Markdown 呈现功能清单与详细说明，语气亲和且专业，避免晦涩的技术术语（如不提“主外键”、“数据库索引”）。生成阶段（阶段 4）：必须输出严格合法的 App Spec JSON 块，确保客户端解析器能直接读取并渲染。迭代阶段（阶段 5）：输入原有 current_spec 和用户修改意见，仅返回增量更新后的新 App Spec JSON，并附带更新日志（Changelog）。6. MVP 核心功能模块清单模块名称职责描述1. 交互与对话中心 (Chat UI)承载用户与 AI 的交互对话界面，支持阶段进度条展示（需求描述 -> 功能清单 -> 详细规格 -> 生成完成）。2. Spec 编译与解析器 (Spec Parser)校验并解析 AI 输出的 App Spec JSON，映射为前端标准数据模型。3. 动态表单引擎 (Dynamic Form)支持根据 Spec 动态生成输入框、下拉框、日期选择器、数值计数器、文本域，并执行必填校验。4. 动态数据表格 (Dynamic Table)承载数据呈现，具备行删除、简易字段搜索、本地导出为 CSV/Excel 的能力。5. 本地存储适配器 (Data Store)负责将不同 App 的数据按照 appId + entityId 隔离存入浏览器持久化存储（如 IndexedDB）。6. App 概览与切换器 (App Drawer/List)允许在同一个界面下切换已生成的不同应用（例如：App1 工时记录、App2 客户登记）。

# Yours App (YA)

> 基于自然语言交互的零代码应用即时生成平台 —— 说出你的业务诉求，四步对话得到一个**能立刻用**的轻量业务管理应用。

本工程是《构思.md》与《UI设计.md》(PRD v2.0) 的**可运行实现**：免登录、本地持久化、配置驱动（Spec-Driven），
支持从零生成应用，也支持在应用详情页「改功能清单 → 联动更新 Spec → 重新构建 → 数据无损迁移」的完整闭环。

## 一、快速开始

```bash
npm install       # 安装依赖（如依赖已就绪可跳过）
npm run dev       # 启动开发服务器（默认 http://localhost:5273）
```

打开浏览器访问提示的地址即可。首次打开会自动植入一个演示应用「员工工时记录助手」（含 14 条示例数据），
可直接进入体验填报、检索、导出、迭代与重建。

### 1.1 配置 AI 对话（推荐，一次配置长期使用）

对话生成默认**走真实大模型**。把接口信息写进环境变量，打开页面即可直接对话，无需每次手填：

```bash
cp .env.example .env.local      # Windows: copy .env.example .env.local
```

编辑 `.env.local`：

```ini
VITE_YA_LLM_BASE_URL=https://api.deepseek.com/v1   # 任何 OpenAI 兼容接口
VITE_YA_LLM_MODEL=deepseek-chat
VITE_YA_LLM_API_KEY=sk-你的密钥
```

重启 `npm run dev` 生效。也可以完全不配环境变量，改为在页面上点 ⚙️ 手填（配置存于浏览器本地）。
顶部与对话区都有 **AI 状态指示**：显示当前模型名，点击即可一键在「AI 对话 / 内置引擎」之间切换。

> **没有 Key 也能用**：内置规则引擎可在完全离线的情况下跑通四步生成闭环，
> 或者在 ⚙️ 里把接口指向本地 Ollama（`http://localhost:11434/v1`）。

### 1.2 其它命令

```bash
npm run build        # 生产构建，产物在 dist/（hash 路由，双击 index.html 也能用）
npm run preview      # 预览构建产物
npm test             # 引擎单元测试（35 项，Node 内置 test runner，零额外依赖）
npm run verify       # 端到端验证（内置引擎模式，真实无头 Chrome 走完整闭环 + 逐步截图）
npm run verify:ai    # 端到端验证（AI 模式，需先启动模拟模型服务，见下）
npm run mock-llm     # 启动本地 OpenAI 兼容模拟服务（无需任何密钥）
```

AI 模式的端到端验证不需要真实密钥，用内置模拟服务即可验证「真的发出 HTTP 请求」：

```bash
npm run mock-llm                                        # 终端 A：监听 127.0.0.1:8787
npm run dev                                             # 终端 B
npm run verify:ai                                       # 终端 C
```

> `verify:ai` 会断言：请求体含 Bearer 鉴权头、`stream:true`、system prompt 带上阶段指引、
> 不含重复的最后一条用户消息；界面渲染出模型名/耗时/token 徽标；模型返回的 Spec 被正确采纳。
> 截图输出在 `verify-shots/`，结果同时写入 `report.json`。

### 1.3 密钥安全边界（务必阅读）

本项目是纯前端应用，浏览器直连模型接口：

- 填在 ⚙️ 面板里的 Key 只存本机 `localStorage`，不会上传到任何服务器；
- 写在 `.env.local` 里的 Key 会被 Vite 在构建时注入前端产物（`.env.local` 已被 `.gitignore` 忽略）；
- 因此 —— **本机自用没问题，但不要把带 Key 的 `dist/` 发布到公网**。
  若要公开部署，应改为请求自建后端代理，由后端保管密钥（前端只发对话内容），
  改动点集中在 `src/engine/llmClient.js` 的请求地址与鉴权方式。

## 三、两种对话引擎

系统内置**双引擎**，可随时一键切换（顶栏与对话区的模式标签就是开关）：

1. **AI 对话（默认，真实调用模型）**
   每一轮用户输入都会真实发起 `POST /v1/chat/completions`：
   流式 SSE 逐字渲染、显示模型名/耗时/token 用量、system prompt 按对话阶段
   （需求描述 / 功能清单 / 详细规格 / 二次迭代）动态切换，并在需要时要求模型输出结构化 App Spec。
   失败**不会静默回退**：界面给出错误分类（配置 / 鉴权 / 限流 / 网络 / 服务端）+
   可操作建议 + 「🔄 重试 / 用内置引擎继续 / ⚙️ 检查配置」三个按钮，生成过程中可随时「■ 停止」。

2. **内置规则引擎（离线兜底）**
   10 个业务领域模板（工时、库存、客户、报销、任务、资产、文档、员工、会议、质检）+ 关键词意图识别 +
   字段推导 + 跨领域功能补充。没有网络、没有 API Key 也能跑通完整四步闭环。

两种模式产出的 App Spec **格式完全一致**，可随时互相切换，历史数据不受影响。

## 五、关键设计决策

1. **不生成源码，生成 Spec**
   所有应用都由同一套「动态表单 + 动态表格 + 本地存储」引擎驱动，AI 只产出结构化 Spec，
   因此不存在生成不可控代码的问题，重建也只是替换 Spec 并迁移数据。

2. **真实调用优先，失败必须可见**
   一旦启用 AI 模式，每轮对话都真实请求模型；出错时抛出带分类的 `LlmError`，
   由界面给出可操作提示与「重试 / 手动降级」按钮，而不是偷偷换成内置引擎——
   静默回退会让用户误以为「模型在回答」，是产品上的严重误导。

3. **模型给出 Spec 也不跳过确认**
   模型往往在第二轮就输出完整 Spec。系统只把它落到「详细规格」阶段，
   必须由用户点击「确认并生成应用」才会真正建应用，保持 PRD 的 4 步确认语义。

4. **字段只在编译期推导，功能清单只保留业务语言**
   功能清单里不缓存字段定义。否则用户在详情页删掉的字段，会在下一次重编译时被「长回来」——
   这是实现过程中真实踩到的坑，现已由「字段来源可追溯」的四条规则约束：
   已有 Spec 字段 → 领域模板核心字段（仅首次创建）→ 本轮新增功能的数据项 → 用户点名要的字段。

5. **意图与描述分离**
   字段推导只认「用户本轮说过的话」（intent），不认应用描述。描述里的「工作内容」等词
   曾把已删字段重新推导出来，分离后行为变得确定可测。

6. **删除即归档，不静默丢数据**
   删除字段重建时，旧值移入记录的 `_archived`，并在确认弹窗中明确告知影响范围，
   未勾选确认无法点击构建。

7. **唯一 key 保障**
   中文标签无法转拼音，字段 key 采用「前缀 + 标签哈希」，保证同一 Spec 内唯一
   （曾因两个中文字段拿到同一个 key，导致删除与迁移只生效一个）。

8. **Vue 非深响应带来的两个坑（已在代码注释中标注）**
   流式追加的消息必须**替换 `messages` 数组中的条目**才会重渲染，直接改对象字段不生效；
   `emit` 不返回值，因此「一句话改功能清单」的结果由组件直接调用服务层获取，
   避免父子组件互相等待造成的死锁。

## 七、已知边界

- 按 MVP 要求**不设登录与权限**，同一浏览器内的数据对所有人可见；多人协作需后续引入后端。
- 数据保存在浏览器本地，清理浏览器数据会同时清空应用与记录，请使用「导出配置」备份。
- 内置规则引擎对**发散型长句**的理解有限（这是规则引擎的固有边界），
  复杂需求请配置真实模型；两者可随时切换，数据格式完全一致。
- 生成能力聚焦「单数据表 + 表单/表格页面」的轻量应用，暂不支持多表关联与复杂流程审批。
- 纯前端直连模型接口，因此受浏览器 **CORS** 限制：个别厂商的接口不允许浏览器直接调用时，
  需要自建后端代理转发（届时前端只需改 `llmClient.js` 的请求地址）。
